# 胡迪视频工作站

React / Vite 前端，配套豆包本地浏览器服务。

## 首次安装

在本目录打开 PowerShell，建议使用 Node.js 22.12+ LTS：

```powershell
npm ci
npm run doubao:install
```

## 本地运行

打开两个终端，均进入本目录。

终端 1：

```powershell
npm run doubao:server
```

豆包服务默认监听 `http://127.0.0.1:8787`。保持终端开启；添加账号时，在弹出的浏览器中完成登录，再回到此终端按回车。

终端 2：

```powershell
npm run dev
```

打开 Vite 输出的地址（通常为 `http://localhost:5173`）。`doubao:server` 只启动豆包接口，不提供前端页面。真实生成需要在页面中配置相应 API 或登录豆包账号。

## 检查与构建

```powershell
npm test
npm run build
npm run preview
```

测试包含本地 Chromium 测试，需先运行 `npm run doubao:install`。`preview` 预览 `dist` 中的构建结果，豆包服务仍需单独运行。

## 提交代码

`scripts/commit.mjs` 依次完成「状态检查 → 文件暂存 → 提交」，并校验提交信息是否符合中文格式规范。默认只暂存本次指定的文件，不使用 `git add -A`，避免把未完成的改动一并提交。

```powershell
npm run commit -- -t feat -m "新增批量提交" -b "支持一次提交多条提示词" -b "输入栏宽度自适应"
npm run commit:list
```

提交类型可用 `feat`、`fix`、`docs`、`style`、`refactor`、`perf`、`test`、`build`、`ci`、`chore`、`revert`。主题行写成「类型: 中文描述」，需要范围时写成「类型(范围): 中文描述」；正文每条要点用 `- ` 开头。描述中的半角逗号、括号等会自动转为中文标点，路径、版本号和 `commit:list` 这类标识符保持不变。

常用选项：

| 选项 | 说明 |
|------|------|
| `-f, --file <路径>` | 指定本次提交的文件，可重复传入；默认取工作区全部改动 |
| `--dry-run` | 只展示将要提交的内容，不真正提交 |
| `--staged-only` | 只提交已手动暂存的改动 |
| `--allow-empty-body` | 允许没有正文要点 |
| `--require-tests` | 测试未通过时中止提交，默认仅提示 |
| `--skip-tests` | 跳过提交前的 `npm test` |
| `--no-verify` | 提交时跳过 git 钩子校验 |

提交前默认运行一次 `npm test`，但仅提示不拦截：依赖本地 Chromium 的用例在未安装浏览器时会失败，强制拦截会导致无法提交。需要严格校验时加 `--require-tests`。

## 常见问题

- 选题使用「生文配置」中的模型。DeepSeek 等没有内置搜索的模型由应用先通过 `60s.viki.moe` 的公开接口获取所选平台热榜，再筛选科普选题；接口需支持 Responses 或 Chat Completions。单个平台取数失败会提示并跳过，全部失败时停止，不生成猜测的热点。热度和来源按本次获取的原始数据展示。

- 使用本机 Chrome 或 Edge 导入镜头文件夹并允许写入后，视频生成完成会自动保存到所选首帧图片所在的文件夹。文件名为「镜头1.mp4、镜头2.mp4…」；已有同名文件时依次保存为「镜头1 (2).mp4、镜头1 (3).mp4…」，不会覆盖已有视频。无镜头编号时使用原图名称。先前导入的项目需点击「关联原文件夹」重新选择图片目录。保存失败会保留生成结果，点击「保存视频」仅重试保存，不会重新生成或消耗额度。页面需保持打开；文件夹授权不包含在数据备份中。

- `ENOENT ... package.json`：确认终端在本目录，且下载或复制了完整项目。不要只复制 `src` 和 `scripts`。
- `Executable doesn't exist`：运行 `npm run doubao:install` 安装与当前 Playwright 匹配的 Chromium。
- “查看本次豆包窗口”：上传和发送期间聚焦当前任务窗口；取得对话地址后，窗口关闭也可用原账号重新打开对应对话，不重复发送。连续点击只恢复一个窗口。发送成功后的五分钟等待期内，重新打开会继续读取视频结果；等待结束后仍可重开查看，但不会自动重新读取。尚未取得任何对话地址就关闭窗口时，需用原账号手动检查豆包历史记录。
- 本次窗口记录保存在服务内存中，重启豆包服务后旧按钮无法恢复之前的窗口；先保存需要的豆包对话链接。
- 如果豆包历史任务为空：服务会用同一账号的独立页面检查本次提示词能否重新读到。校验失败只标为待确认，不把发送页本地显示的消息或临时对话地址当成已保存任务。请保留原窗口，检查发送错误、网络和登录状态；不会自动补发。
- 活动任务的“查看本次豆包窗口”只聚焦，不刷新或导航原窗口。消息出现后的延迟地址变化只有在本次提示词仍可读时才允许更新绑定。消息消失超过 15 秒会停止读取并保存诊断；诊断包含导航、查看按钮事件和接口 HTTP 状态，便于区分主动导航、页面重渲染和请求失败。
- 自动发送从豆包主聊天页点击“视频生成”，确认技能选中后上传图片，等待图片预处理成功，再通过键盘写入新版编辑器。旧 `/chat/create-video` 专页仍能加载，但实测提交返回 `710020702` 并清空消息，服务已改用主聊天入口。
- 只读监听网页发出的 `/chat/completion` 和旧 `/samantha/chat/completion` 请求。HTTP 200 不等于业务成功，返回业务错误码会停止等待并显示错误，不自动重发。`/chat/0` 和 `local_…` 属于无效或临时地址，不可用来恢复任务。阶段和响应摘要实时追加到 `data/doubao-diagnostics/*.jsonl`，不记录请求正文、认证头或完整回复。
- 页面出现消息仍属于待确认；读到本次回复且独立页面确认消息已保存后，才标记受理。发送接口报错会立即结束发送等待。`710022004` 表示发送受限（RateLimit / LIMIT_TO_SEND_MESSAGE），可能只留下草稿；检查原窗口提示，如有验证要求请手动完成，稍后再确认是否可以发送。程序不会自动重发或扣减本地次数。
- 批量视频逐镜头处理，前一镜头完成后才发送下一镜头；遇到失败、待确认或跟踪超时，会暂停其余镜头并标记尚未发送。同一账号在服务端也会排队，已排队任务遇到前序失败或未完成时会停止发送。发送限制由豆包决定，排队不能保证解除已存在的限制。
- 本次视频对话出现“视频生成参数确认”“确认后开始生成”等明确请求且回复稳定后，自动回复“确认，请按上述参数开始生成视频。”，每个镜头最多一次，然后继续验证确认消息是否保存并跟踪视频。人工已回复或编辑器中有输入时不会覆盖；补充材料、登录验证、无法生成等提示保留人工处理。确认发送失败时停止跟踪，不自动重发。
- 8787 端口被占用：关闭此前启动的服务；或设置 `$env:DOUBAO_PORT = '8788'` 后启动，并在页面中同步修改本地服务地址。
- `mock:api` 也默认使用 8787，不能与豆包服务同时占用此端口；需要时用 `MOCK_IMAGE_API_PORT` 指定另一端口。

账号会话保存在 `data/doubao-accounts/`，请勿公开或提交这些文件。
